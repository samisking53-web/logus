LOG US 구글 로그인·회원가입 서버(Firebase) 연결 설정 순서
==============================================================

로그인 수단은 구글 계정 하나만 쓴다(카카오 로그인은 쓰지 않기로 함).
앱 코드는 이미 연결돼 있다. 아래는 사람이 Firebase·Google Cloud·Vercel 콘솔에서 직접 해야 하는 설정이다.
(콘솔은 계정 권한이 필요해서 Claude가 대신할 수 없다. 메뉴 이름은 콘솔 개편에 따라 조금 다를 수 있다.)

Firebase 프로젝트 ID: logus-80f21
아래에서 <앱주소> 라고 쓴 곳에는 0단계에서 정한 주소(예: logus.vercel.app)를 넣는다. https:// 는 빼고 쓴다.

[로그인·회원가입이 동작하는 방식]
1) 로그인 화면(/login)에서 "Google로 시작하기"를 누른다.
   - 폰: 구글 로그인 페이지로 이동했다가 앱으로 돌아온다(redirect)
   - PC: 작은 구글 로그인 창이 뜬다(popup)
2) Firebase Authentication 이 구글 계정을 확인하고 회원(uid)을 만든다. 이미 있으면 그 회원으로 로그인한다.
3) 처음 온 사람은 회원가입 화면(/signup)에서 닉네임을 정하고 "가입 완료"를 누른다.
   → Firestore 의 users/{uid} 문서(닉네임·프로필 사진·가입 시각)가 만들어진다.
   → 보안 규칙(firestore.rules)이 "본인 문서만, 정해진 필드만" 쓸 수 있게 막아 준다.
4) 그다음부터는 로그인만 하면 바로 홈으로 간다.


0. 먼저 정할 것: 로그인 테스트용 고정 주소
----------------------------------------------
- Vercel 미리보기 주소는 PR마다 바뀌어서 로그인 설정에 등록할 수 없다.
- 실서비스 주소(예: logus.vercel.app)를 정하고, 필요하면 staging 주소도 하나 정한다.
  (Vercel → logus 프로젝트 → Settings → Domains 에서 확인. 기본으로 <프로젝트이름>.vercel.app 이 있다)
- 로그인 테스트는 이 고정 주소에서만 한다. 미리보기 주소에서는 로그인이 안 되는 게 정상이다.


1. Firebase에 웹 앱 등록과 환경변수
----------------------------------------------
1) Firebase 콘솔(console.firebase.google.com) → logus-80f21 → 프로젝트 설정(톱니바퀴) → 일반 → 내 앱
2) 웹 앱(</> 아이콘)을 추가한다. 앱 이름은 LOG US. Firebase Hosting 설정은 체크하지 않는다.
3) 화면에 나오는 firebaseConfig 값 6개를 확인한다.
4) Vercel → logus 프로젝트 → Settings → Environment Variables에 아래 6개를 넣는다.
     NEXT_PUBLIC_FIREBASE_API_KEY             = apiKey
     NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN         = <앱주소>   ← firebaseapp.com 주소가 아니라 앱 주소를 넣는다
     NEXT_PUBLIC_FIREBASE_PROJECT_ID          = logus-80f21
     NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET      = storageBucket
     NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID = messagingSenderId
     NEXT_PUBLIC_FIREBASE_APP_ID              = appId
   - AUTH_DOMAIN을 앱 주소로 두는 이유: 폰에서는 페이지 이동(redirect)으로 로그인하는데,
     요즘 브라우저(사파리 등)는 다른 도메인의 로그인 정보를 막는다. 그래서 앱 주소의 /__/auth/ 를
     Firebase로 대신 연결해 두었다(next.config.ts의 rewrites).
   - 이 값들은 공개돼도 괜찮다(권한은 보안 규칙이 지킨다). 그래도 코드에는 넣지 않고 환경변수로만 넣는다.
   - NEXT_PUBLIC_USE_FIREBASE_EMULATORS 는 Vercel에 넣지 않는다(로컬 개발 전용).
5) 넣은 뒤 Vercel에서 다시 배포(Redeploy)해야 반영된다.
6) 로컬에서 진짜 Firebase로 돌려 보려면 저장소의 .env.example 을 .env.local 로 복사해 같은 값을 넣는다.
   (로컬에서는 AUTH_DOMAIN 을 logus-80f21.firebaseapp.com 으로 둔다)


2. 구글 로그인 켜기
----------------------------------------------
1) Firebase 콘솔 → Authentication → (처음이면 "시작하기") → 로그인 방법 → 새 제공업체 추가 → Google
2) 사용 설정 ON → 프로젝트 지원 이메일을 고르고 저장한다.


3. 승인된 도메인 등록
----------------------------------------------
1) Firebase 콘솔 → Authentication → 설정 → 승인된 도메인 → 도메인 추가
2) <앱주소>를 추가한다. staging 주소가 있으면 그것도 추가한다.
   (localhost와 logus-80f21.firebaseapp.com은 기본으로 들어 있다)


4. 구글 리디렉션 주소 등록 (폰 로그인용)
----------------------------------------------
1) Google Cloud 콘솔(console.cloud.google.com) → 위쪽에서 프로젝트 logus-80f21 선택
   → API 및 서비스 → 사용자 인증 정보
2) OAuth 2.0 클라이언트 ID 목록에서 "Web client (auto created by Google Service)"를 연다.
   (2단계에서 구글 로그인을 켜면 Firebase가 자동으로 만든다)
3) 승인된 자바스크립트 원본에 추가:   https://<앱주소>
4) 승인된 리디렉션 URI에 추가:        https://<앱주소>/__/auth/handler
   - staging 주소가 있으면 둘 다 같은 형식으로 추가한다.
5) 저장. 반영까지 몇 분 걸릴 수 있다.
6) (선택) API 및 서비스 → OAuth 동의 화면 → 앱 이름을 LOG US 로, 지원 이메일을 팀 이메일로 바꾸면
   구글 로그인 화면에 프로젝트 ID 대신 앱 이름이 보인다.


5. 보안 규칙·색인 배포 (회원가입 문서 저장에 필요)
----------------------------------------------
회원가입은 Firestore users/{uid} 에 저장한다. 저장소의 보안 규칙이 배포돼 있어야 저장된다.
배포 담당이 로컬 컴퓨터에서(클라우드 세션 말고) 승인 후 실행한다.
     firebase login
     firebase use logus-80f21
     firebase deploy --only firestore:rules,firestore:indexes
- Firestore 데이터베이스를 아직 만들지 않았다면 먼저 콘솔 → Firestore Database → 데이터베이스 만들기
  (위치: asia-northeast3 서울, "프로덕션 모드")
- Storage 규칙과 서버 함수 배포는 PR 설명의 명령을 따른다(로그인·회원가입에는 필요 없음).


6. 확인
----------------------------------------------
1) 폰에서 https://<앱주소> 를 연다 → 로그인 화면이 나온다.
2) "Google로 시작하기" → 구글 계정 선택 → 회원가입 화면이 나온다(닉네임에 구글 이름이 들어 있음).
3) "가입 완료" → 홈에 닉네임과 "보유 0 코인"이 보인다.
4) Firebase 콘솔
   - Authentication → 사용자: 구글 계정이 생겼는지
   - Firestore → users → (uid): nickname·photoURL·createdAt 이 있는지
5) 마이로그 → 로그아웃 → 다시 로그인하면 회원가입 없이 바로 홈으로 간다.


7. 안드로이드 앱(android/ 폴더)을 쓸 때 추가 설정
----------------------------------------------
안드로이드 앱은 웹과 같은 Firebase 프로젝트·같은 구글 로그인을 쓴다(같은 사람은 같은 계정).
1) Firebase 콘솔 → 프로젝트 설정 → 일반 → 앱 추가 → Android
   - 패키지 이름: com.logus.app
2) SHA-1 지문 등록(팀원 각자): Android Studio에서 signingReport 실행 → debug 의 SHA1 값을
   Firebase 콘솔 → 내 앱(Android) → 디지털 지문 추가. (자세한 방법은 android/README.md)
   SHA-1이 없으면 안드로이드 구글 로그인이 실패한다.
3) google-services.json 을 내려받아 android/app/ 에 넣는다.
   2단계(구글 로그인 켜기)와 SHA-1 추가를 마친 뒤에 받아야 한다. 이 파일은 커밋하지 않는다.
4) 안드로이드 앱은 지금 회원가입 화면 없이, 처음 로그인할 때 구글 이름으로 프로필을 자동으로 만든다.


8. 끝나면 Claude에게 알려 줄 것
----------------------------------------------
- 0단계에서 정한 고정 주소(실서비스, staging)
- 1~5단계를 마쳤는지, 6단계 확인 결과(안 되면 화면에 나온 오류 문구 그대로)
- 키 값(apiKey 등)은 보내지 않아도 된다. 콘솔과 Vercel에만 저장되고 코드에는 들어가지 않는다.


자주 막히는 곳
----------------------------------------------
- "redirect_uri_mismatch" 오류(구글 화면)
  → 4단계 리디렉션 URI를 https://<앱주소>/__/auth/handler 형식으로 정확히 등록했는지 확인한다(끝 / 없음).
- 앱에 "이 주소에서는 로그인을 쓸 수 없어요"
  → 3단계 승인된 도메인에 지금 접속한 주소가 있는지 확인한다. 미리보기 주소는 원래 안 된다.
- 앱에 "구글 로그인이 아직 켜져 있지 않아요"
  → 2단계를 확인한다.
- 앱에 "Firebase 설정값이 없어서 로그인할 수 없어요"
  → 1단계 환경변수를 넣고 Vercel에서 다시 배포한다.
- 구글 로그인은 됐는데 "가입하지 못했어요"
  → 5단계 보안 규칙 배포, Firestore 데이터베이스 생성을 확인한다.
- 카카오톡·인스타그램에서 링크를 열면 로그인이 안 됨
  → 구글 정책으로 막혀 있다. 앱이 '크롬으로 열기 / Safari로 열기' 안내를 보여 준다.
