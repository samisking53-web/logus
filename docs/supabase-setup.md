# Supabase 서버 붙이기 안내 (소셜 로그인 없이, 공동 피드까지)

> 카카오·구글 로그인 없이 **앱 안 가입만으로** 서버를 붙이는 방법입니다.
> 서버를 붙이면 계정·여정·기록(영상)이 각자의 폰이 아니라 Supabase에 저장됩니다. 그래서 **같은 여정에 초대된 친구끼리 기록을 함께 볼 수 있습니다.**
>
> - 나중에 카카오·구글 로그인도 붙일 때는 `docs/login-setup.md`의 5~6번을 이어서 하면 됩니다.
> - 2026년 9월 기준으로 정리했습니다. Supabase·Vercel 화면이 바뀌면서 메뉴 이름은 조금씩 달라질 수 있으니, 비슷한 이름을 찾아 들어가세요.

## 0. 한눈에 보기

**지금 (실습 단계)**

```
내 폰 브라우저   ── 계정·여정(localStorage), 영상(IndexedDB)
친구 폰 브라우저 ── 친구 것만 따로 저장
→ 서로의 기록을 볼 수 없음
```

**서버를 붙인 뒤**

```
내 폰   ─┐                 ┌─ Auth     : 계정 (이메일·비밀번호)
         ├── Supabase ─────┼─ Postgres : 프로필·여정·구성원·기록 (DB 표)
친구 폰 ─┘                 └─ Storage  : 영상·첫 장면·대표 화면 파일
```

- 누가 무엇을 볼 수 있는지는 DB의 **RLS(행 단위 권한 규칙)** 가 정합니다. "여정 구성원만 그 여정의 기록을 본다"를 앱이 아니라 DB가 지켜 줍니다.
- 할 일은 두 종류입니다.
  - **A. 사람이 대시보드에서 하는 설정**: 1~6장. 한 번만 하면 되고 30분 정도 걸립니다.
  - **B. 앱 코드 바꾸기**: 7장. Claude에게 **세션 4번**에 나눠 요청합니다(CLAUDE.md: 한 세션에 기능 하나).

## 1. 먼저 정할 것

아래 네 가지를 팀에서 먼저 정합니다. 표의 **추천**대로 하면 이 문서를 그대로 따라갈 수 있습니다.

| 정할 것 | 추천 |
|---|---|
| ① 로그인 아이디 | **이메일로 바꾸기** |
| ② 가입 확인 메일 | **보내지 않기** |
| ③ 지금 폰에 있는 실습 데이터 | **옮기지 않고 새로 가입** |
| ④ Supabase 프로젝트 주인 | **팀원 한 명**이 만들고 나머지를 초대 |

**① 왜 아이디 대신 이메일인가요?**
- Supabase의 비밀번호 로그인은 **이메일**(또는 전화번호)로만 됩니다. "아이디"라는 칸이 없습니다.
- 아이디를 `아이디@example.com` 같은 가짜 이메일로 바꿔 넣는 방법도 있지만, Supabase가 `example.com`·`test` 같은 가짜 주소를 막아서(`email_address_invalid` 오류) 쓸 수 없습니다.
- 바뀌는 화면은 가입 **2/4 단계** 하나입니다. "아이디" 칸이 "이메일" 칸이 됩니다. 약관 동의(1/4)·닉네임(3/4)·준비 완료(4/4)는 그대로이고, 앱에 보이는 이름도 지금처럼 **닉네임**입니다.

**② 왜 확인 메일을 안 보내나요?**
- 가입하자마자 바로 쓸 수 있습니다(메일함에 가서 링크를 누를 필요 없음).
- Supabase 기본 메일 서버는 **팀원 이메일로만, 아주 적은 수만** 보낼 수 있습니다. 일반 사용자에게 메일을 보내려면 메일 서비스(예: Resend)를 따로 연결해야 합니다.
- 대신 알아 둘 점
  - 확인을 안 하니 **남의 이메일 주소로도 가입할 수 있습니다.** 캡스톤 시연에는 문제없지만, 실제로 서비스를 열 때는 확인 메일을 켜야 합니다.
  - **비밀번호 찾기**도 메일이 필요해서, 메일 서비스를 연결하기 전에는 만들 수 없습니다(지금과 같음).

**③ 실습 데이터**: 지금 폰에 저장된 계정·여정·영상은 연습용이라 서버로 옮기지 않습니다. 서버를 붙인 뒤 새로 가입합니다.

## 2. Supabase 프로젝트 만들기 (주인 한 명)

1. [supabase.com](https://supabase.com) → **Start your project** → GitHub 계정으로 로그인
2. **Organization** 만들기: 이름 `logus-team`, 플랜 **Free**
3. **New project**
   - Name: `logus`
   - Database Password: **Generate** 버튼으로 만들고, 비밀번호 관리자처럼 안전한 곳에 보관합니다.
     - 앱은 이 비밀번호를 쓰지 않습니다. 코드·채팅·카톡에 붙여 넣지 않습니다.
   - Region: **Northeast Asia (Seoul)**: 한국에서 가장 빠릅니다.
   - 그 밖의 선택 칸은 기본값 그대로 둡니다. **Data API**를 켜고 끄는 칸이 보이면 **켜 둡니다**(앱이 DB를 읽는 통로).
4. 1~2분 기다리면 프로젝트가 준비됩니다.
5. **팀원 초대**: Organization 화면 → **Team** → **Invite** → 팀원 이메일, 역할은 **Developer** 이상
   - 팀원도 SQL Editor·Table Editor를 쓸 수 있게 됩니다.

### 무료 플랜 한도 (캡스톤 시연에는 충분)

| 항목 | 한도 | 우리 앱에서는 |
|---|---|---|
| DB | 500MB | 글·숫자만 들어가서 거의 안 참 |
| 파일(Storage) | 1GB | 10초 영상 하나가 폰에 따라 약 3~10MB → **100~300개** |
| 내려받기(egress) | 한 달 5GB (+캐시 5GB) | 영상을 한 번 볼 때마다 그 크기만큼 씀 |
| 파일 하나 | 50MB | 10초 영상은 충분 |
| 프로젝트 수 | 2개 | |
| **일시정지** | **7일 동안 아무도 안 쓰면 멈춤** | 멈추면 앱에서 로그인이 안 됨 |

- **일시정지 주의**: 방학·시험 기간에 일주일 넘게 안 쓰면 프로젝트가 멈춥니다. 대시보드에 **Paused**가 보이면 **Restore**를 누르면 됩니다(몇 분 걸림). **발표 전날 꼭 한 번 들어가 확인**하세요.
- 영상 파일이 커서 Storage·내려받기 한도가 먼저 찹니다. 코드 작업 4에서 영상 화질(비트레이트)을 정해 파일 크기를 줄이는 것을 권합니다.

## 3. 로그인 설정 (이메일·비밀번호)

Supabase → **Authentication → Sign In / Providers**

1. **User Signups** 부분

   - **Save**
3. Kakao·Google은 지금은 켜지 않습니다.

- **Site URL**: 앱의 정식 주소 (Vercel 프로젝트 → Settings → Domains에 보이는 주소)

## 4. 앱과 연결하는 값 넣기 (환경변수)

### 4-1. 값 복사하기

Supabase 화면 위쪽 **Connect** 버튼, 또는 **Project Settings → API Keys**(와 **Data API**)에서 두 값을 복사합니다.

- **Project URL**: `https://abcdefgh.supabase.co` 모양
- **Publishable key**: `sb_publishable_…`로 시작

이 두 값은 **브라우저에 보여도 되는 값**입니다. 누가 이 값을 알아도 RLS 규칙이 허락한 데이터만 볼 수 있습니다.

> ⚠️ **절대 쓰지 않는 값**: `sb_secret_…`(secret key), `service_role` 키, DB 비밀번호
> - 이 값이 있으면 RLS를 무시하고 **모든 사람의 데이터를 읽고 지울 수 있습니다.**
> - 코드·커밋·채팅·카톡, Vercel의 `NEXT_PUBLIC_…` 변수 어디에도 넣지 않습니다.
> - 실수로 노출됐다면 **API Keys** 화면에서 그 키를 바로 지우고 새로 만듭니다.

### 4-2. Vercel에 넣기

1. Vercel → `logus` 프로젝트 → **Settings → Environment Variables**
2. 두 개를 추가합니다. **Production, Preview, Development**를 모두 체크합니다.

   | 이름 | 값 |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
   | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key |

3. **Deployments** 탭 → 맨 위 배포 → **⋯ → Redeploy**. 환경변수는 다시 배포해야 반영됩니다.

- 지금 앱 코드는 아직 Supabase를 부르지 않아서, 환경변수를 넣어도 앱은 달라지지 않습니다. 미리 넣어 두면 코드 작업 결과를 미리보기 주소에서 바로 확인할 수 있습니다.

### 4-3. 내 컴퓨터에서 개발할 때

저장소 맨 위에 `.env.local` 파일을 만들고 두 줄을 넣습니다. 이 파일은 `.gitignore`에 있어 커밋되지 않습니다.

```
NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

### 4-4. Claude(클라우드 세션)가 서버에 닿게 하기 (선택)

지금 Claude가 일하는 클라우드 환경은 네트워크 규칙 때문에 `*.supabase.co`에 접속할 수 없습니다. 이대로도 코드는 만들 수 있지만, Claude가 **실제 서버로 직접 확인**하게 하려면:

1. 세션 제목 줄의 **클라우드 환경 메뉴 → Edit → Network access**에서 허용 도메인에 `*.supabase.co`를 추가합니다(문서를 읽게 하려면 `supabase.com`도).
2. 같은 화면의 환경변수에 위 두 값(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`)을 넣습니다. **publishable key만** 넣고 secret key는 넣지 않습니다.
3. 새 세션부터 적용됩니다. 키 값은 채팅에 붙여 넣지 않습니다.

## 5. DB 표 만들기 (SQL Editor)

DB 표와 권한 규칙은 저장소의 `supabase/migrations/` 파일로만 만듭니다. 팀원이 대시보드에서 **번호 순서대로 한 번씩** 실행합니다.

| 순서 | 파일 | 내용 | 지금 상태 |
|---|---|---|---|
| 0001 | `0001_profiles_and_agreements.sql` | 프로필(닉네임), 약관 동의 기록 | 있음 (코드 작업 1에서 이메일 가입에 맞게 다시 확인) |
| 0002 | 여정 | 여정, 구성원, 같은 여정 구성원끼리 닉네임 보기, 파일 보관함(Storage) | 코드 작업 2에서 만듦 |
| 0003 | 초대 | 초대 코드로 여정 요약 보기·참여하기 | 코드 작업 3에서 만듦 |
| 0004 | 기록 | 기록, 함께한 사람(`log_tags`), 영상 파일 권한 | 코드 작업 4에서 만듦 |
| 이후 | 댓글·반응·코인·추억 영상 | `comments`·`reactions`·`coin_ledger`·`recaps` | 그 화면을 만들 때 |

**실행하는 법 (파일마다 같음)**

1. Supabase → **SQL Editor → New query**
2. 파일 내용을 **처음부터 끝까지 전부** 복사해 붙여 넣고 **Run**
3. `Success. No rows returned`가 나오면 성공입니다.
4. **Table Editor**에서 새 표가 보이는지, 표 이름 옆에 **RLS disabled**나 **Unrestricted** 표시가 없는지 봅니다.
5. **Advisors → Security Advisor**에서 경고가 없는지 봅니다.
6. 팀 채팅방에 "0002 실행 완료"처럼 남깁니다. 누가 어디까지 실행했는지 모르면 순서가 꼬입니다.

- 같은 파일을 두 번 실행하면 "already exists"(이미 있음) 오류가 납니다. 이미 실행된 것이니 그냥 두면 됩니다.
- 순서를 건너뛰면 "does not exist"(없음) 오류가 납니다. 앞 번호부터 실행합니다.

## 6. 영상 보관함 (Storage)

- 0002 SQL이 파일 보관함(버킷)을 **비공개(Private)** 로 만듭니다. Supabase → **Storage**에서 보관함 이름 옆에 **Public** 표시가 **없는지** 확인합니다.
- 파일 위치는 CLAUDE.md 규칙대로 여정별로 나눕니다.
  - 영상: `journeys/{여정 번호}/{기록 번호}.mp4` (Chrome은 `.webm`)
  - 영상 첫 장면: `journeys/{여정 번호}/{기록 번호}.jpg`
  - 대표 화면: `journeys/{여정 번호}/cover.jpg`
- **그 여정의 구성원만** 파일을 올리고 볼 수 있습니다.
- 보관함이 비공개라서, 앱은 영상을 틀 때마다 **잠깐만 열리는 주소(signed URL)** 를 받아 재생합니다. 그 주소가 밖으로 퍼져도 시간이 지나면 열리지 않습니다.

### 작업 3. 친구 초대 (초대하기 · I01 · I02)

- **바뀌는 것**

- **SQL**: 0003
- **확인**: A가 초대 링크를 카톡으로 보냄 → B가 열어서 가입 → 참여 → B의 마이로그에 그 여정이 보이고, 여정 상세 구성원이 "A·B"로 보임

## 8. 폰 2대로 최종 확인 (시연 시나리오)

1. **폰 A**: 가입 → 오늘이 들어간 여정 만들기 → **친구 초대하기**로 링크를 카톡으로 보냄
2. **폰 B**: 카톡에서 링크 열기 → 여정 요약이 보임 → 가입 → 여정에 참여
3. **폰 A**: 영상 찍기 → 게시
4. **폰 B**: 마이로그 → 여정 상세 → **A의 영상**과 "함께한 사람 · A"가 보이는지
5. **폰 B**도 영상을 올리고, 폰 A에서 두 영상이 **방문 일시 순서**로 보이는지
6. **폰 C**(여정에 없는 사람): 여정 상세 주소를 직접 쳐서 들어가도 **"여정을 찾을 수 없어요."** 가 나오는지 (권한 확인)
7. 폰 A에서 로그아웃 → 다시 로그인해도 기록이 그대로 있는지

## 9. 문제가 생기면

| 보이는 증상 | 원인·확인할 곳 |
|---|---|
| 가입할 때 "Email address … is invalid" | `example.com` 같은 가짜 주소. 실제로 있는 이메일 주소로 가입 |
| 가입 후 "Email not confirmed" | 3장 **Confirm email**이 켜져 있음 |
| 앱이 아무것도 못 불러옴, "Invalid API key" | 4장 환경변수 값 오타, 또는 Redeploy를 안 함 |
| "permission denied for table …" | SQL 파일의 일부만 실행함(`grant` 줄이 빠짐). 파일 전체를 다시 확인 |
| "new row violates row-level security policy" | 권한 규칙에 맞지 않는 저장(예: 구성원이 아닌 여정에 기록). 앱 버그일 수 있으니 오류 문구 그대로 Claude에게 전달 |
| "relation … does not exist" | SQL을 순서대로 실행하지 않음. 5장 표 순서 확인 |
| "already exists" | 같은 SQL을 두 번 실행함. 이미 된 것이니 무시 |
| 영상 올리기 실패 "exceeded the maximum allowed size" | 파일이 50MB를 넘음 |
| 갑자기 전부 안 됨, 대시보드에 **Paused** | 7일 미사용 일시정지. **Restore** |
| 로그인·가입이 잠깐 막힘 "rate limit" | 짧은 시간에 가입·로그인을 아주 많이 함. 잠시 후 다시, 또는 **Authentication → Rate Limits** |
| 미리보기 주소에 Vercel 로그인 화면이 뜸 | Vercel → Settings → Deployment Protection → Vercel Authentication 끄기 |

## 10. 꼭 지킬 것 (보안)

- **secret key·service_role 키·DB 비밀번호**는 어디에도 붙여 넣지 않습니다(4-1).
- **RLS를 끄지 않습니다.** "권한 오류가 나서 RLS를 껐더니 됐다"는 해결이 아니라, 모든 사람에게 데이터를 여는 것입니다.
- 대시보드의 **Table Editor·SQL Editor는 관리자 권한**이라 RLS와 상관없이 모든 데이터가 보입니다. "친구가 이걸 볼 수 있나?"는 반드시 **앱에서 다른 계정으로** 확인합니다(8장 6번).
- 이메일·위치(좌표)·영상은 개인정보입니다. 탐색(S08)에는 `is_public = true`이고 좌표가 있는 기록만 나갑니다(CLAUDE.md).
- 테스트 계정 정리: **Authentication → Users**에서 지우면 그 사람의 프로필·약관 동의 기록도 함께 지워집니다.
